# Project Summary
Forge is an AI application-building workspace that turns project descriptions into reviewable plans and generated applications. Users can manage projects, approve plans, track and retry builds, chat with an agent, manage memories, preview applications, export source code, and provide feedback on task results.

Supabase stores project and workflow data. A persistent Node.js worker uses configurable LLM providers and Daytona sandboxes to plan, build, and repair applications. Versioned plans and execution leases protect workflows from stale writes. Optional Langfuse observability records execution traces, timing, and available token usage.

Project deletion is staged: a project is marked for deletion, the Worker removes its recorded sandbox, and project-scoped data is deleted. If sandbox removal fails, the project remains available for retry. User preferences and non-sensitive audit metadata are retained separately.

## Project Module Description
- **Frontend workspace:** Authentication, project management, plan review, task history and retries, chat, memory management, code browsing, previews, source export, and task feedback.
- **Project deletion:** Requires typing lowercase `delete`. Deletion invalidates active executions and blocks new work. The Worker deletes only the project’s recorded Daytona sandbox; failures leave the project available for retry.
- **Memory management:** Separates user preferences from project conventions. Users can manage memories and enable or disable preferences. The Worker proposes user-level preferences but does not save them without user confirmation.
- **Task feedback:** Project owners can submit and view categorized feedback for completed or failed tasks. Feedback is associated with the task and execution version and removed with its project.
- **Audit and retention:** Records operational metadata without prompts, code, secrets, or tokenized preview URLs. Audit records are independent of project deletion and retained for a configurable period, defaulting to 90 days.
- **Worker and sandbox:** Claims tasks, executes agent tools, checks leases, processes project deletion, cleans expired audit records, and manages Daytona sandboxes. An administrator-only command supports safe orphan-sandbox review.
- **Backend security:** PostgreSQL migrations configure row-level security, ownership constraints, grants, RPCs, deletion safeguards, feedback access, audit records, and retention cleanup.
- **Testing and mock UI:** PGlite tests cover database security and workflow behavior; Worker tests cover workflows including deletion. `/ui-mock` is for interface checks only and does not connect to live services.

## File Description Inventory
- `app/backend/migrations/0003_deletion_retention.sql` — Adds staged project deletion, safeguards, feedback and audit tables, memory preference controls, and configurable audit retention. Apply after migrations `0001` and `0002`.
- `app/backend/tests/deletion.test.mjs` — PGlite coverage for deletion, ownership, feedback, audit, and retention behavior.
- `app/frontend/src/pages/Projects.tsx` — Shows deletion scope, requires exact confirmation, and presents retry status.
- `app/frontend/src/components/MemoryPanel.tsx` — Separates user preferences from project conventions and provides management controls.
- `app/frontend/src/components/TaskFeedback.tsx` — Collects categorized feedback and optional details for eligible tasks.
- `app/frontend/src/components/TaskPanel.tsx` — Displays the task feedback entry point.
- `app/frontend/src/lib/data.ts` and `app/frontend/src/lib/supabase.ts` — Define and access application data.
- `app/worker/src/deletion.js` — Processes project sandbox cleanup and expired audit-record cleanup.
- `app/worker/src/admin-sandboxes.js` — Reviews Daytona sandboxes by ownership labels; deletion requires an explicit ID and confirmation.
- `app/worker/src/sandbox/daytona.js` — Labels new sandboxes with project and user identifiers and treats an already-missing sandbox as deleted.
- `app/worker/src/memory.js` — Excludes disabled preferences from task context and proposes preferences without automatically saving them.
- `app/worker/src/index.js`, `app/worker/src/agent.js`, and `app/worker/src/config.js` — Integrate worker processing, deletion, and retention configuration.
- `app/worker/tests/deletion.test.js` — Tests deletion processing and retry behavior, sandbox handling, and memory preferences.
- `README.md` — Documents migration order, Worker setup, sandbox operations, audit retention, and privacy-conscious regression-sample handling.

## Technology Stack
- **Frontend:** React, TypeScript, Vite, Tailwind CSS, and shadcn-style UI components.
- **Backend and data:** Supabase, PostgreSQL, row-level security, and RPC functions.
- **Worker:** Node.js 20+, JavaScript, ReAct agent, configurable LLM providers, and optional Langfuse/OpenTelemetry tracing.
- **Sandbox:** Daytona SDK behind the `SandboxProvider` abstraction.
- **Testing and packaging:** PGlite, ESLint, Docker, and ZIP export.

## Usage

### Database migration
Apply migrations in order: `0001_init.sql`, `0002_plan_review.sql`, then `0003_deletion_retention.sql`. If migrations `0001` and `0002` are already applied, apply only `0003`.

### Configure environment
- **Frontend:** Set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in `app/frontend/.env`.
- **Worker:** Set `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, an LLM key (`DEEPSEEK_API_KEY` or `ZHIPU_API_KEY`), `DAYTONA_API_KEY`, and `DAYTONA_API_URL` in `app/worker/.env`.
- **Audit retention:** Set `AUDIT_RETENTION_DAYS` in the Worker environment; the default is 90 days.
- Optional Langfuse settings are worker-only. Keep service-role, provider, and observability secrets out of frontend configuration and source control.

### Install, run, and validate
Frontend:
```bash
cd app/frontend
pnpm install
pnpm run dev
pnpm run lint
pnpm run build
```

Worker:
```bash
cd app/worker
npm install
npm test
npm run check
npm run doctor
npm start
```

Review Daytona sandboxes from the Worker environment. The default command is non-destructive; deletion requires an explicit sandbox ID and confirmation:
```bash
npm run admin:sandboxes
npm run admin:sandboxes -- --delete <sandbox-id> --confirm
```
Unlabeled legacy sandboxes are classified as unknown and are not automatically deleted.

Backend tests:
```bash
cd app/backend/tests
npm install
node rls.test.mjs
node plan.test.mjs
node deletion.test.mjs
```

Build the Worker container:
```bash
docker build -t forge-worker ./app/worker
```
